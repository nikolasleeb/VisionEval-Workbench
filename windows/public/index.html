Before you create a Hypercube

!

Hypercubes are safe to run on a laptop.

Windows runs one VisionEval case at a time. Larger matrices can take many hours and use substantial memory and workspace storage, and the computer may feel slower while a case is running.

Version 2 limit: up to two parameter axes and 400 generated scenarios per Hypercube keeps experiments bounded.

On computers with less than 16 GB of RAM, use small matrices and close other memory-intensive applications. This is guidance, not a block.

A 9 × 9 matrix creates 81 complete scenario runs and 81 serialized execution waves.

Calculating a planning estimate from comparable completed runs…

Runtime varies with model stages, population, years, outputs, computer performance, and resource contention. A future verified container or cloud runtime may support parallel cases; parallel execution is not available in Windows 2.0.

VisionEval inputs are type-sensitive. Declared count fields must remain whole numbers, while continuous numeric inputs can use the precision selected here. Runtime Setup Guide

  1. Detect or choose an existing installationSelect VE_RUNTIME, VE_HOME, and Rscript.exe independently. VE_RUNTIME and VE_HOME must be separate folders; neither may be inside the other.
  2. Or install the certified pairIf no usable VE_RUNTIME is found, choose Install R 4.5.3 + VisionEval RC7. Workbench installs for the current user without administrator privileges and verifies pinned SHA-256 checksums.
  3. Verify the connectionWorkbench starts the selected R installation, checks native capabilities, and identifies RC7 from the VECommit metadata stored in the package DESCRIPTION files.

Suggested locations are %USERPROFILE%\VE_Home and %LOCALAPPDATA%\VisionEval\VE_Runtime. The workspace is separate and may remain on an external SSD. If downloads are unavailable, install the pinned files manually and choose the three existing paths here.

  1. Install and start Docker DesktopDocker Desktop is required only for model runs and uncached R data.
  2. Select Install runtimeWorkbench pulls the immutable Apple Silicon image, creates the local alias, and performs the complete verification automatically.
  3. Run modelsAfter verification, Workbench creates temporary containers only while jobs are running.
